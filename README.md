# Demo Data Generator — v3.0

Industry/domain- and geography-aware demo data generator for sales demos.
Every field's value is generated by a real LLM call — nothing is templated,
randomly assembled, or pulled from a fixed list at the content level.

This is the merged, completed build described in the v3.0 remediation spec:
the new codebase's structure (`Agents/`, `workflow/`, `service/`, `main.py`,
`frontend/src/`) as the base, with every capability the old build had
restored, the specific product decisions applied, and the observed APM
save bug fixed at its root cause.

## Structure

```
backend/     FastAPI + LangGraph backend (Python 3.11+)
frontend/    React + Vite frontend
```

## Quick start

### Backend

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # or your preferred env tool
pip install -r requirements.txt
cp .env.example .env    # then fill in OPENAI_API_KEY, SOURCE_GITLAB_*, DATABASE_URL, APM_DOC_HOST
uvicorn main:app --reload --port 8000
```

On first startup, `service/settings_service.py` auto-creates its own
Postgres table — no separate migration step.

### Frontend

```bash
cd frontend
npm install
cp .env.example .env    # VITE_API_BASE_URL, defaults to http://localhost:8000
npm run dev
```

## What changed from the two source builds

See the original remediation spec for the full rationale. In short:

- **Every generated value is LLM-produced.** No Faker, no `random`/regex
  content generation anywhere in the data path. The one exception is the
  identifier-dedup safety net (`steps/identifier_dedup.py`), which only
  disambiguates an accidental duplicate — it never invents content.
- **No Excel export.** The editable preview table is the only output
  surface; APM save is the only persistence path.
- **The external save target is never named for real anywhere** — code,
  filenames, env vars, UI copy, comments. It's referred to as "APM"
  throughout.
- **Geography is a structured, validated selector** — Continent → Country
  → State/Region, backed by `pycountry`, with both a cascading top-down
  picker and a reverse, worldwide-searchable quick-search box.
- **Domain + Subdomain replace the old separate Industry/Domain fields.**
  Final settings surface: Module, Screen, Domain, Subdomain, Geography.
- **No editable Backend URL in the UI** — the frontend always talks to
  `VITE_API_BASE_URL`, fixed at build time.
- **Login configuration lives in a sidebar drawer**, not a persistent top
  bar — click "Login" in the left nav.
- **APM save is fully wired and fixed at the root cause.** APM's real
  save-schema types are resolved *before* generation runs, so the Data
  Generator Agent produces correctly-typed values (e.g. a real integer for
  a `{"type":"integer","format":"byte"}` field) from the start, instead of
  generating display text that later 400s. `tools/row_mapper.py` still
  coerces/clamps defensively as a second line of defense.
- **Fuzzy-first resolution, schema caching, and full-module generation are
  all restored.** A blank Screen now generates every real screen under a
  module in one request, with a single shared cross-screen entity
  assignment pass so recurring picklist fields (e.g. "Status") show the
  same values on every screen.
